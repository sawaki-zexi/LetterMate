# LetterMate 产品需求

**状态：** 当前有效
**更新日期：** 2026-07-29

## 1. 产品定位

LetterMate 是面向个人的高精度信息发现工作台。系统同时提供两类发现：用户用一个完整关键词建立的精准 Topic 追踪，以及不依赖预设 Topic 的技术趋势发现。两类结果都必须经过多来源搜索、正文补全、事实支持过滤、去重和 AI 评审，最终在统一 Feed 中显示带原始链接的中文摘要。

产品优先减少低价值和无法支持核心事实的内容，不追求结果数量。没有合格内容时，空结果是正常成功状态。

## 2. 核心流程

### 2.1 关键词追踪

1. 用户输入 1-100 字符的完整关键词创建 Topic。
2. 系统立即入队首次发现，并生成不扩大主题边界的查询变体。
3. 启用且适用的连接器并发搜索；单个可选渠道失败不阻塞其他渠道。
4. 候选必须命中完整关键词或仅改变大小写、空格、连字符等形式的确认变体。
5. 系统验证来源证明和 HTTP(S) URL，补全正文，并完成事实支持过滤、历史增量判断、精确与近似去重。
6. 合格结果生成 `hot | quality` 中文摘要、推荐理由和原始链接。

版本、型号和带标点标识符必须保持完整。例如 `gpt-5.7` 不得宽化为 `GPT`、`latest GPT model` 或“人工智能”，也不得把 `gpt-5.7.1` 当作 `gpt-5.7` 的匹配结果。确定性别名只能处理不改变含义的标点和空格形式，例如 `gpt-5.7`、`gpt 5.7` 和 `gpt5.7`。

### 2.2 趋势发现

1. 系统从 X/TwitterAPI.io、Hacker News、YouTube、Reddit、Bilibili 和配置的 Google Trends RSS 收集有限的热门候选。
2. 趋势榜单条目只作为 `TrendSeed` 搜索种子；榜单出现、热度或顺序不是事实证明，不能直接进入 Feed。
3. 系统先筛选 AI、技术、软件产品、工程和研究等目标垂直领域，再保留产品名、项目名和版本标识构造精准查询。
4. 系统复用主发现连接器，从网页、社交、视频、社区、代码、论文和 Feed 中查找正文、一手记录或其他支持材料。
5. 候选经过正文补全、事实支持门控、精确与近似去重、历史去重、来源多样性选择和中文摘要生成。
6. 只有最终合格的 `RadarItem` 才会出现在统一 Feed；没有支持材料时不创建条目。

## 3. 功能需求

### 3.1 账号与所有权

- Topic、TrendMonitor、运行记录、发现结果和刷新操作必须属于当前用户。
- 跨用户访问返回 `404`，不暴露资源是否存在。
- Web 只调用 LetterMate API，不直接访问 OpenRouter、趋势源或其他连接器，也不读取任何密钥。

### 3.2 调度与运行一致性

- 新 Topic 创建后立即运行，之后按 6、12 或 24 小时自适应更新；版本型关键词仍按完整标识符精准追踪。
- Topic 连续高产可缩短到 6 小时，连续空结果可延长到 24 小时；周期带不超过 10% 的确定性抖动。
- 每个用户拥有一个默认每 4 小时运行的 TrendMonitor；`TREND_INTERVAL_HOURS` 可配置为 2-24 的整数。
- PostgreSQL 的 `nextRunAt` 是两类调度的真实状态，调度器每 10 分钟扫描到期任务。
- 手动刷新不改变 Topic 的长期统计、自适应周期或趋势的自动周期。
- 同一 Topic 或 TrendMonitor 不得并发运行多个任务；运行中再次刷新只登记一次待处理手动刷新。
- 最终失败保留已有结果，只返回安全错误；不得保存半成品发现条目。

### 3.3 主发现连接器与趋势输入

主发现连接器实际包括：

- OpenRouter Web Search 和可选 Brave-compatible Search；
- X/TwitterAPI.io、Bluesky；
- RSS/Atom、Hacker News、arXiv、GitHub；
- YouTube、Bilibili、Reddit。

趋势输入实际包括 X/TwitterAPI.io Trends、Hacker News Top Stories、YouTube Most Popular、指定 Reddit 社区 Hot、Bilibili 热门和配置的 Google Trends RSS。GitHub、arXiv、RSS/Atom 和通用 Web 可以用于趋势种子的后续检索与支持验证；GitHub 不作为趋势榜单输入。

- X 必须通过 TwitterAPI.io 接入，不使用 Cookie、模拟登录、验证码绕过或非授权抓取。
- 缺少可选密钥或 Feed URL 时，只禁用对应渠道；公共渠道仍可运行。
- 连接器必须验证平台响应 schema、内容 ID、时间和 HTTP(S) 原始 URL。
- 原创帖、官方公告、维护者说明、代码 Release、论文记录和作者线程可作为一手信息。
- 转发、无新增信息的引用、纯情绪评论、搜索页、分类页和无法补足上下文的内容不得入库。

### 3.4 高精度与事实支持

- 网页必须取得正文；视频必须有足够说明、章节、字幕或文字稿；论文至少有标题、作者和摘要；代码内容至少有 README、Release Notes 或实质讨论。
- 只根据标题、缩略图、趋势榜单或搜索摘要生成结果属于不合格行为。
- 标题中的发布、上线、融资、政策变化等核心事实必须得到所提供正文或一手平台记录支持；传言、戏仿、无支持声明和标题正文冲突必须拒绝。
- AI 只能从服务端验证过的候选池选择 URL，不能新增、改写或猜测 URL。
- 按平台内容 ID、规范化 URL、标题和内容指纹去重，并与用户历史比较信息增量。
- 通常返回 3-8 条；不足时允许更少或为空，不降低质量或事实支持门槛。
- `hot` 表示近期关注增长、密集更新或重要发布，`quality` 表示内容具有明显信息增量；二者都不是事实核验状态。

### 3.5 统一 Feed、筛选与分组

- Feed 合并 Topic 的 `DiscoveryItem` 和趋势的 `RadarItem`，卡片分别显示“关键词追踪”或“趋势发现”。
- 时间范围固定为 `1d | 3d | 7d | 30d | 90d | all`，默认 `30d`；历史永久保留。
- 来源筛选固定为 `all | topic | trend`，并可组合 `hot | quality`；`topicId` 不能与 `origin=trend` 组合。
- API 按 `publishedAt ?? discoveredAt` 在服务端过滤和倒序排序。
- Web 使用互斥的“今天、昨天、近 3 天、近 7 天、本月更早、更早”分组，并省略空分组。
- 卡片显示平台、内容类型，以及可用的作者或账号信息；外部链接在新标签页安全打开。

### 3.6 手动刷新反馈

- 发现页刷新范围由当前筛选决定：指定 Topic 只刷新该 Topic；`topic` 刷新 Topic；`trend` 刷新趋势；`all` 刷新 Topic 和趋势。
- 点击刷新和移动端顶部下拉刷新使用同一协调逻辑；刷新期间按钮设置 `aria-busy=true`，图标显示进行中状态，已有 Feed 保持可浏览。
- 页面显示非阻塞进度，并只根据请求开始之后、`trigger=manual` 的持久化运行摘要判断完成。
- 所有目标结束后重新读取 Feed，并以持久化 `newItemCount` 的总和显示权威结果，例如“刷新完成，新增 3 条内容”；零新增、部分失败和全部失败使用明确状态。
- Topic 页面每一行只显示该 Topic 自己的刷新状态，不阻塞其他 Topic。

### 3.7 用户可见状态边界

- 用户可查看连接器的 `enabled | not_configured` 安全状态和运行的排队、进行中、成功或失败状态。
- 产品不显示可信分数、来源排名、证据数量、事实核验标签、“已核实”或内部 AI 支持判断。
- 状态接口不得返回 Key、鉴权头、配额、上游地址、完整外部正文或内部错误。

## 4. 配置与安全

- `AI_API_KEY` 是主题扩展、趋势垂直分类、候选评审和最终中文内容生成的基础要求。
- 外部服务凭据为 `TWITTERAPI_IO_API_KEY`、`GITHUB_TOKEN`、`YOUTUBE_API_KEY`、`REDDIT_CLIENT_ID`、`REDDIT_CLIENT_SECRET`、`SEARCH_API_KEY`；搜索服务还使用 `SEARCH_PROVIDER` 和可选 `SEARCH_API_BASE_URL`。
- Feed 配置为 `DISCOVERY_RSS_FEED_URLS` 和 `TREND_GOOGLE_RSS_URLS`；趋势控制项为 `TREND_MONITOR_ENABLED`、`TREND_INTERVAL_HOURS`、`TREND_X_WOEIDS`、`TREND_YOUTUBE_REGION`、`TREND_REDDIT_COMMUNITIES`。
- 所有密钥、Session/CSRF secret、Authorization 和 `x-api-key` 只存在于 API/Worker 服务端，不得进入浏览器、数据库公开字段、日志、错误响应或测试快照。
- 外部正文抓取必须防 SSRF，拒绝本地、私网、链路本地、云元数据地址和不安全重定向，并限制 MIME、大小和超时。
- `.env.example` 只保留空值或明确的非敏感默认值；真实 `.env` 永远不提交版本库。

## 5. 本期不包含

- 用户自定义来源规则、来源优先级或黑白名单界面。
- 用户可见的可信评分、事实核验状态、证据计数、来源排名或内部 AI 判断。
- 浏览器内密钥管理、模拟登录、个人 Cookie 抓取或验证码绕过。
- 通用新闻热点承诺；自动趋势聚焦技术、AI、软件产品、工程和研究。
- 邮件、Push、团队协作、付费能力和完整社交数据仓库。

## 6. 验收标准

1. `gpt-5.7` 等完整关键词不会被宽化，也不会匹配 `gpt-5.7.1`。
2. 趋势榜单只产生种子；通过垂直分类、多源搜索、正文补全和事实支持门控后才可进入 Feed。
3. 配置适用连接器时覆盖多类真实来源；缺少可选 Key 时公共渠道仍可运行。
4. 自动趋势默认每 4 小时执行，Topic 按 6/12/24 小时执行，手动刷新不改变自动周期。
5. 刷新立即显示 `aria-busy` 和非阻塞进度，完成数量来自持久化运行摘要。
6. Feed 提供六个时间范围、三种来源筛选和互斥时间分组，默认近 30 天。
7. 每条结果都有有效原始 URL 和可回溯来源；低价值、无支持、转载和重复内容被过滤。
8. 所有资源执行用户所有权检查，外部密钥和内部判断不泄漏。
9. UI 不出现可信分数、来源排名、证据数量或“已核实”标签，并在桌面、平板、手机和 320px 视口无水平溢出。
10. 默认测试不联网；Prisma 生成与迁移、lint、typecheck、单元/集成测试、构建和端到端测试通过。

# LetterMate 产品需求

**状态：** 当前有效
**更新日期：** 2026-07-27
## 1. 产品定位

LetterMate 是面向个人的高精度信息发现工作台。用户只输入一个主题关键词，系统自动扩展中英文查询，从搜索引擎、社交媒体、视频平台、RSS 和技术社区发现近期内容，统一筛选后生成带原始链接的中文摘要。

产品优先减少低价值文章，而不是追求结果数量。没有合格内容时，空结果是正常成功状态。

## 2. 核心流程

1. 用户输入 1-100 字符的关键词创建主题。
2. 系统立即入队首次发现，并生成有限、去重的中英文扩展词。
3. 启用且适用的连接器并发召回候选；单个可选渠道失败不阻塞其他渠道。
4. 系统验证来源证明与 URL，过滤过期、薄内容、搜索页、采集页、纯转载和历史重复。
5. 剩余候选经过正文补全、近似去重、AI 批量评审和来源多样性选择。
6. 用户查看 `hot | quality` 中文摘要、推荐理由、平台与作者信息，并可打开原始内容。
7. 系统按 6、12 或 24 小时自适应更新；用户也可手动刷新。

## 3. 功能需求

### 3.1 账号与所有权

- 主题、发现结果、运行和刷新操作必须属于当前用户。
- 跨用户访问返回 `404`，不暴露资源是否存在。
- Web 只调用 LetterMate API，不直接访问外部连接器或读取密钥。

### 3.2 主题与调度

- 同一用户不能创建规范化后相同的主题。
- 创建后立即触发首次运行，并显示排队、运行、成功或失败状态。
- 首次成功后默认 12 小时更新；连续高产可缩短到 6 小时，连续空结果可延长到 24 小时。
- 调度间隔只允许 6、12、24 小时，并加入不超过 10% 的确定性抖动。
- 手动刷新不改变下一次自动更新时间和长期调度统计。
- 同一主题不得并发运行多个发现任务；单次运行允许 5-10 分钟，默认总时限为 10 分钟。
- 最终失败保留旧结果，并提供安全且真实的错误状态。

### 3.3 多源发现

- 首批来源包括通用 Web 搜索、X/Twitter、RSS/Atom、Hacker News、arXiv、GitHub、YouTube、Bilibili、Reddit 和 Bluesky。
- X 必须通过 TwitterAPI.io 接入，不使用 Cookie、模拟登录、验证码绕过或非授权抓取。
- 支持 Brave-compatible Search；其他搜索引擎可在统一连接器契约后增量接入。
- 缺少可选密钥时，仅将对应连接器标记为待配置；公共渠道仍可运行。
- 连接器必须验证平台响应 schema、内容 ID、发布时间和 HTTP(S) 原始 URL。
- 原创帖、官方公告、维护者说明和作者线程可直接作为一手信息，不能仅因篇幅短而降级。
- 转发、无新增信息的引用、纯情绪评论和无法补足上下文的帖子不得入库。

### 3.4 高精度质量

- 网页必须取得正文；视频必须有足够说明、章节、字幕或文字稿；论文至少有标题、作者和摘要；代码内容至少有 README、Release Notes 或实质讨论。
- 只根据标题、缩略图或搜索摘要生成结果属于不合格行为。
- AI 只能从服务端验证过的候选池选择 URL，不能新增、改写或猜测 URL。
- 按平台内容 ID、规范化 URL、标题和内容指纹去重，并与主题历史比较信息增量。
- 通常返回 3-8 条；不足时允许更少或为空，不降低质量阈值。
- 同一域名或平台默认不超过最终结果的 40%；结果不足 3 条时可放宽多样性，但不能放宽质量。
- `hot` 表示近期关注增长、密集更新或重要发布，`quality` 表示内容具有明显信息增量；二者都不是事实核验状态。

### 3.5 Feed 与历史

- Feed 支持主题、`hot | quality` 和时间范围筛选。
- 默认显示最近 90 天；用户可以切换到永久保留的全部发现历史。
- 卡片显示平台、内容类型，以及可用的作者或账号信息。
- 外部链接在新标签页安全打开；详情显示全部原始链接。
- 界面不得显示来源可信等级、证据等级、评分或“已核实”等措辞。

### 3.6 来源状态与错误

- 用户可查看连接器的 `enabled | not_configured` 安全状态。
- 状态接口不得返回 Key、鉴权头、配额、上游地址或内部错误。
- 至少一个连接器成功且质量管线完成时，运行成功，包括空结果。
- 所有计划连接器失败、AI 评审失败或最终结构非法时，运行失败且不保存半成品。
- 单个候选正文抓取失败时可使用已验证的 API 正文；信息仍不足则丢弃。

## 4. 配置与安全

- `AI_API_KEY` 是运行发现的基础要求；OpenRouter 负责主题扩展、AI 质量评审和最终中文内容生成。
- `TWITTERAPI_IO_API_KEY` 启用 X；GitHub Token、YouTube Key、Reddit OAuth、搜索服务 Key 和 RSS Feed 均为可选配置。
- 密钥、Authorization、`x-api-key`、完整外部正文和敏感上游响应不得进入浏览器、数据库、日志、错误响应或测试快照。
- 外部正文抓取必须防 SSRF，拒绝本地、私网、链路本地、云元数据地址和不安全重定向，并限制 MIME、大小和超时。
- `.env.example` 仅保留空值或明确假值，真实 `.env` 不提交版本库。

## 5. 本期不包含

- 用户自定义来源规则、来源优先级或黑白名单界面。
- 来源评分后台、事实核验状态机、证据计数或“可信/已确认”状态。
- 浏览器内密钥管理、模拟登录、个人 Cookie 抓取或验证码绕过。
- 邮件、Push、团队协作、付费能力和完整社交数据仓库。

## 6. 验收标准

1. 单关键词即可创建主题并触发多源发现。
2. 配置适用连接器时至少覆盖四类真实来源；缺少可选 Key 时仍能使用公共渠道。
3. 配置 TwitterAPI.io 后可以发现并展示原创 X 帖子和线程。
4. 低价值、薄内容、转载和重复内容被过滤，一手短讯不会因长度被误杀。
5. 每条结果都有有效原始 URL 和可回溯的来源证明。
6. 自动更新遵循 6/12/24 小时规则，手动刷新不改周期，同一主题不并发运行。
7. Feed 默认 90 天并可查看全部永久历史。
8. 局部失败可降级，整体失败保留旧结果，敏感配置不泄漏。
9. 默认测试不联网；lint、typecheck、单元测试、构建、迁移验证和端到端测试通过。

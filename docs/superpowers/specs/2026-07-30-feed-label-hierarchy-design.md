# Feed 标签层级简化设计

**状态：** 待实施
**日期：** 2026-07-30

## 1. 背景与目标

当前发现页同时把“关键词追踪 / 趋势发现”和“热点 / 优质”作为醒目标签展示，并在顶部提供两组分段筛选。前一组描述发现路径，后一组描述内容价值；两个不同维度使用相近的视觉权重，导致卡片和筛选区标签过多，用户难以判断首先应该关注什么。

本次调整的目标是：

- 以“为什么值得看”作为卡片的第一视觉层级。
- 保留发现路径，但将其降级为具体、易理解的上下文说明。
- 合并来源与 Topic 筛选，减少顶部控件数量。
- 不改变现有发现管线、后端枚举、查询能力或刷新语义。

## 2. 已确认方案

采用“双层信息、单一主标签”方案。

### 2.1 卡片信息层级

- `hot` 继续显示为“热点”。
- `quality` 在所有用户界面统一显示为“精选”，不再显示“优质”。
- 每张卡片只将“热点”或“精选”渲染为醒目的主标识。
- Topic 条目的发现路径显示为弱化文字：`来自「<完整关键词>」`。
- Trend 条目的发现路径显示为弱化文字：`来自全网趋势`。
- 不再显示“关键词追踪”或“趋势发现”。
- 平台、内容类型、作者和发布时间继续作为普通元信息显示。平台是文章来源，发现路径是用户看到该内容的原因，两者不得合并。

Topic 关键词必须沿用服务端返回的完整值，不得做语义改写。过长关键词在卡片中单行截断，承载文本的元素同时使用完整关键词作为 `title` 和 `aria-label`；移动端不得因此产生水平滚动。

### 2.2 详情页

详情页与卡片使用相同的价值文案映射：`hot -> 热点`、`quality -> 精选`。详情页不新增评分、可信状态、证据数量或来源排名。

### 2.3 顶部筛选

顶部保留一组价值分段控件：

- 全部
- 热点
- 精选

原有“全部 / 关键词追踪 / 趋势发现”分段控件与独立 Topic 下拉框合并为一个“来源”下拉框：

- 全部来源
- 全网趋势
- 用户已有的每个 Topic，以完整关键词作为选项文本

筛选映射保持现有 API 契约：

| UI 选择 | API 查询 |
| --- | --- |
| 全部来源 | `origin=all`，无 `topicId` |
| 全网趋势 | `origin=trend`，无 `topicId` |
| 具体关键词 | `origin=topic`，并传对应 `topicId` |

时间范围筛选保持不变。桌面端和移动端使用同一套筛选语义；移动端使用紧凑下拉，不增加新的筛选行。

## 3. 交互与数据流

前端继续以现有 `origin`、`topicId`、`kind` 和 `range` 状态构造 Feed 查询，不修改共享 contracts 或 API 路由。来源下拉的单个选中值在前端转换为 `origin + topicId`：选择具体 Topic 时设置 `origin=topic`，选择其他来源时清空 `topicId`。

刷新范围继续由转换后的筛选状态决定：

- 具体关键词只刷新对应 Topic。
- 全网趋势只刷新 TrendMonitor。
- 全部来源刷新全部 Topic 与 TrendMonitor。

切换来源时必须原子更新 `origin` 和 `topicId`，避免出现 `origin=trend` 携带旧 `topicId` 的无效中间状态。现有刷新进度、持久化运行因果关系、时间分组和 Feed 失效刷新逻辑保持不变。

## 4. 组件边界

- `DiscoveryCard`：负责价值主标识、发现路径说明以及现有来源元信息。
- `FeedPage`：负责统一来源下拉、价值分段控件以及 UI 值到现有查询参数的映射。
- `ItemPage`：复用统一的价值显示文案。
- 共享契约和后端：不变，继续使用 `hot | quality` 与 `topic | trend`。

实现时应在 Web 内提供单一的显示文案映射，避免卡片、详情和筛选分别硬编码“精选”。本次不引入新的通用设计系统或修改无关页面。

## 5. 状态与异常处理

- Topic 列表加载前，来源下拉仍可显示“全部来源”和“全网趋势”；加载完成后补充 Topic 选项。
- 当前选中的 Topic 被删除或不再存在时，自动回退到“全部来源”，并清空 `topicId`。
- Topic 加载失败时沿用现有错误反馈；不得阻止用户查看“全部来源”或“全网趋势”的现有 Feed。
- 空结果、Feed 加载失败、趋势状态失败和刷新失败继续使用现有反馈，不新增标签型错误状态。

## 6. 可访问性与响应式要求

- 价值分段控件保留可识别的分组名称和 `aria-pressed` 状态。
- 来源下拉必须有可见标签“来源”。
- “热点 / 精选”不能只依赖颜色区分，继续保留文字与图标。
- 截断的 Topic 来源说明必须能访问完整关键词。
- 在 1440px、平板、常规手机和 320px 紧凑视口下不得出现水平溢出、文字遮挡或控件换行导致的布局跳动。

## 7. 测试与验收

更新或新增 Web 测试，覆盖：

1. Topic 卡片显示“来自「关键词」”，且不再显示“关键词追踪”。
2. Trend 卡片显示“来自全网趋势”，且不再显示“趋势发现”。
3. `quality` 在卡片和详情页显示为“精选”。
4. 来源下拉的三类选择正确生成 `origin` 与 `topicId` 查询。
5. 从具体 Topic 或全网趋势切回全部来源时清除旧 `topicId`。
6. 当前 Topic 消失时筛选回退到全部来源。
7. 刷新范围仍与当前来源选择一致。
8. Playwright 在桌面、平板、手机和 320px 视口验证筛选、卡片文案及无水平溢出。

完整验证执行：

```powershell
npm run lint
npm run typecheck
npm test
npm run build
npm run test:e2e
```

## 8. 非目标

- 不修改 `hot | quality` 或 `topic | trend` 的数据库及 API 枚举。
- 不调整内容质量判断、趋势分类、搜索来源或去重规则。
- 不新增可信度、事实核验、证据数量、来源排名或评分。
- 不改变 Topic 精确关键词边界。
- 不重新设计主题管理页、卡片正文或详情页信息架构。

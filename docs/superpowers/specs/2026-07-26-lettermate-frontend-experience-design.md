# LetterMate 前端体验优化设计

**日期：** 2026-07-26  
**状态：** 已批准，待实施

## 背景与目标

当前发现页和主题页的信息结构清楚，但刷新期间没有可见状态变化，用户无法判断操作是否生效。页面同时以灰白平面布局为主，品牌辨识度和交互层次不足。

本次改造实现两个目标：

1. 所有手动刷新操作都提供即时、持续且可访问的进度反馈，并在结束后明确显示结果。
2. 将界面升级为专业的未来感信息工作台，通过颜色、层次和克制动效提升辨识度，同时保持高密度内容的阅读效率。

后端接口、数据模型和产品功能范围不变。

## 设计方向

采用“未来感工作台”风格：石墨色侧栏、浅色内容区、青绿色主色和琥珀色热点强调。主区域使用低对比度数据网格、细线与状态信号增强技术感，不使用影响阅读的大面积装饰、霓虹背景或高强度持续动画。

视觉层级从高到低为：页面标题与全局状态、筛选和主要操作、发现内容、辅助元数据。卡片不嵌套卡片，页面分区保持无框架布局。

## 刷新交互

### 发现页

发现页使用 React Query 的 `isFetching` 表示后台刷新，不移除已有内容。

- 点击刷新后，按钮立即进入禁用状态，图标持续旋转。
- 发现列表保留原内容并降低少量对比度，列表顶部出现横向扫描光带。
- 工具区下方显示紧凑状态条“正在同步最新发现…”，并通过 `aria-live="polite"` 播报。
- 请求成功后，状态条切换为“已更新 · HH:mm”，短暂保留后淡出。
- 请求失败时保留旧数据，状态条显示失败信息与重试按钮。
- 初次加载继续使用现有加载空状态；扫描反馈只用于已有数据的后台刷新。

刷新状态按照 `idle -> refreshing -> success | error` 流转。新的筛选条件导致的查询也使用同一后台刷新反馈，避免页面看似无响应。

### 主题页

主题刷新使用 mutation 当前变量识别被点击的主题，只影响对应行。

- 被点击行的刷新按钮禁用且旋转，其他主题仍可操作。
- mutation 返回 `queued` 后，现有主题轮询继续驱动 `queued -> running -> succeeded | failed`。
- 等待中和搜索中的状态徽标显示轻量脉冲，并在行内增加细进度轨迹。
- 创建主题按钮在提交期间显示旋转图标和“正在创建”，防止重复提交。
- API 错误继续显示现有错误内容，不隐藏主题或扩展词。

## 视觉系统

### 外壳与导航

- 桌面侧栏改为石墨色，品牌标识、当前导航和 OpenRouter 在线状态使用清晰对比色。
- 内容背景保持偏冷的浅灰白，并叠加低对比度固定网格纹理。
- 页面顶部加入细窄信号线，活动请求期间沿水平方向移动。
- 移动端顶部栏和底部导航使用高对比半透明表面与背景模糊，确保内容滚动时仍可辨认。

### 内容与控件

- 发现卡片使用 6px 圆角、分类色左边标记、轻量阴影和清晰边框。
- 卡片首次出现时分批淡入并上移；悬停时最多上移 2px，不造成布局跳动。
- 热点使用琥珀色，优质内容使用青绿色，错误使用红色；避免单一色系统治页面。
- 分段控件、输入框、选择器和按钮统一高度、聚焦环和过渡时间。
- 标签降低边框与文字对比度，移动端允许自然换行，避免扩展词形成视觉噪音。
- 详情页延续同一排版、分隔线和来源链接交互。

## 响应式与可访问性

- 支持 320px 及以上视口，不产生水平滚动。
- 固定底部导航为页面保留足够安全区，不能遮挡最后一张卡片或主题行。
- 所有图标按钮保留可读的 `title` 和 `aria-label`。
- 动态状态使用 `aria-live`，旋转按钮使用 `aria-busy`，不可重复操作时使用原生 `disabled`。
- `prefers-reduced-motion: reduce` 下关闭扫描、脉冲、分批入场和悬浮位移；状态文案仍完整保留。
- 焦点样式、正文和状态颜色满足可辨识要求，不能仅通过动画传达状态。

## 组件边界与数据流

保持现有单页结构，新增两个小型展示组件：

- `RefreshStatus`：接收刷新阶段、成功时间、错误和重试回调，只负责状态条和可访问播报。
- `ActivitySignal`：根据全局查询或 mutation 活跃状态渲染顶部信号线，不请求数据。

`FeedPage` 负责从 React Query 查询状态映射刷新阶段；`TopicsPage` 负责从 mutation 变量和主题 `runStatus` 映射单行状态。展示组件不依赖 API，便于独立测试。

## 错误处理

- 后台刷新失败时不清空缓存内容。
- 发现页状态条展示可重试错误；初次加载失败仍使用完整错误空状态。
- 单主题刷新失败只影响对应主题的错误提示和按钮状态。
- 成功提示计时器在组件卸载或再次刷新时清理，避免过期状态回写。

## 测试与验收

组件测试覆盖：

- 发现页点击刷新后出现旋转、禁用、状态文案和 `aria-busy`。
- 成功后显示更新时间，失败后旧内容保留且可重试。
- 单主题刷新只禁用并旋转目标行。
- 创建主题期间显示进行中状态。
- `RefreshStatus` 的刷新、成功和失败语义。

浏览器验证覆盖 1440x900 桌面、平板和 412x915 移动视口：

- 刷新动效在请求期间可见，结束后正确收敛。
- 卡片、筛选器、主题标签和固定导航无重叠或横向溢出。
- 内容在刷新期间保持可读。
- 减少动态效果设置下没有持续装饰动画。
- 浏览器控制台无错误，生产构建、类型检查、lint、单元测试和端到端测试通过。
